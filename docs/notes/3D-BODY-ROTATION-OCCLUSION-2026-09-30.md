# 3D Body 旋转时肌肉层叠与明暗跳变（待修复）

记录日期：2026-09-30。证据为用户提供的两张连续角度截图及当前源码检查；尚未做受控材质实验或浏览器复验。本记录是缺陷排查材料，不是已经确认的长期渲染设计。

## 现象与影响

- 首页中央人体转至背面及背面斜角时，背部两侧有大块肌肉颜色突然变暗，转过该角度后又恢复。用户反馈其他部位也大量出现类似层叠遮挡。
- 截图中的异常边界跟随肌肉几何而非 HUD 或页面布局，且随视角变化。当前证据不能确认每块色斑对应的 canonical 肌肉 ID，也不能量化所有受影响部位。
- 这会使训练负荷、动作目标和焦点的颜色投影难以稳定辨认；视觉优先级高，但没有证据表明训练数据或肌肉映射被改写。

## 已定位的渲染路径

`BodyViewer3D.tsx` 在 `frameloop="demand"` 的 Canvas 中加载 `BodyModelScene`，`BodyMotion.tsx` 通过改变模型组的 Y 轴角度展示自转。`BodyModelScene.tsx` 的 `prepareModel` 对每个网格分别创建材质：

- 皮肤：`transparent: true`、`depthWrite: false`、`FrontSide`、`renderOrder = 1`。
- 所有肌肉：`transparent: true`、`depthWrite: false`、`DoubleSide`、`renderOrder = 2`；普通肌肉在状态更新中常用约 `0.78–1` 的 opacity，`partial` 用 `0.62`，有焦点时非焦点降到 `0.28`。
- 肌肉之间只有共同的固定渲染层级，没有按每个像素的实际前后关系决定混合顺序；关闭深度写入还使先绘制的透明肌肉不能为后绘制的肌肉建立遮挡。多个前后交叠的肌肉表面会被混色，旋转后排序和可见表面关系变化，足以解释角度相关的色块与明暗跳变。

**当前最强假设**是透明网格排序／深度遮挡造成的渲染伪影，而非颜色 token、训练强度或自转定时器本身突然变化。截图与材质设置支持这个判断；尚未通过逐层关闭皮肤、肌肉透明度和双面渲染的对照实验确认各因素的贡献。几何本身是否存在互穿或重叠也待排除。

## 复现与验证建议

1. 用固定 fixture 和日期打开首页，等 `Model ready`，暂停自动转动，在背面正视与左右斜视之间缓慢拖动；记录角度相邻的截图，分别检查背部、臀部、上臂及腿部。Neon 和 Graphite 都检查。
2. 在隔离的本地调试分支逐项对照：仅隐藏皮肤、只渲染一侧肌肉、将肌肉临时改为不透明并启用深度写入、恢复双面透明。每次只改一个变量，截图保持相同视角与数据。这样可区分皮肤覆盖、肌肉互遮、背面混合和几何互穿。
3. 确认根因后制定正式的材质／绘制策略；验收需覆盖正面、背面和两侧斜视连续转动，确认同一肌肉的颜色不再无故忽明忽暗，同时保留皮肤轮廓、重点肌肉、选择与拾取行为。检查桌面 1440×900、手机 390×844 和 reduced motion；再运行 `npm run lint:design` 及相关 3D/E2E 校验。

现有 `body-explorer` E2E 只验证 Canvas 像素会随旋转变化、暂停和恢复，以及静态场景的交互；不能证明透明层的视觉排序正确。修复前不得把本问题记为视觉验收通过。
