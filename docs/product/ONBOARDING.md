# 首次建档与首训

新工作区只有必要目录、格式清单和默认关闭的自动计划配置。初始化不写个人事实、计划或案例。人体和公共动作仍可探索；公共动作关系不代表个人适用性。

首页进度由 `GET /api/onboarding` 从正式文件与 runtime/onboarding 草稿推导。无档案显示“建立我的训练档案”，部分档案显示继续，确认后显示首次训练安排；有正式计划直接进入计划阅读（优先今日，否则读取首份计划日期）。读取错误单独显示，不当成空工作区。入口打开现有 DSH Surface，不新增模型调用链或会话数据库。

## 对话与确认

每轮两三个重点：目标和经验 → 时间、场地、器械 → 相关身体情况。未回答的不适、RPE、测量保持未知；详细饮食、体脂和历史重量不阻塞开始。先展示“目前对你的了解”，明确事实、目标、偏好、未知和建议，由用户确认摘要。草稿保存在 runtime/onboarding/，不能让半成品进入正式扫描。

确认后按 CLI 的独立提交步骤保存档案、实际日期指标和用户认可的周期方向。允许中断后恢复；删除 runtime 仍可由正式文件推导进度。年龄需观察日期，短期疲劳不写成永久限制。

通常先确认可调整的短期方向，再生成首次计划；用户只想今天训练时允许最小确认档案和一次性计划。缺历史重量时用 prescription 指引现场选择负重和目标用力，不编造公斤。计划显示目标 RPE/RIR 与负重选择说明。

训练后只保存用户报告或明确确认的完成；计划不能因对话结束自动变为 workout。未知实际重量的计划不能直接当作已完成负重。每日自动任务默认关闭，启用后仍要求确认档案和有效周期。

模型 Key 继续由原设置页和 DSH 管理；不增加正确性验证或建档连接步骤。失败不重置已确认档案。

## 验证边界

静态检查、合成数据测试和浏览器空态证据与真实模型写入分开记录。当前未通过真实模型调用证明分轮问答、摘要确认和重启会话恢复的完整端到端行为；不得将规则注入测试视为模型遵循证明。交付证据见 [验证记录](../engineering/DATA-SEPARATION-VALIDATION.md)。
