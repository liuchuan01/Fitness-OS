# 可替换视觉系统：运行时主题包与设计边界

2026-10-01 · 主站主题扩展采用声明式目录包。当前协议与安装步骤见 [主题包作者指南](THEME-PACK-AUTHORING.md)；本文件保留设计边界和历史方向，不将代码完成等同于视觉基线批准。

## 1. 结论与当前证据

建议做“产品专属设计系统 + 声明式主题包”。主题可载入颜色、字体、圆角、层次、光效及身体材质参数；人体布局、训练语义、键盘行为与可访问名称由产品组件负责。用户可以换掉 Cyberpunk，仍然使用同一套训练流程。

迁移前代码审计快照（历史估算依据，不是当前代码计数）：`src/` 有 8 个 CSS 文件、3,306 行；`src/styles.css` 2,488 行，其中正则扫描发现 268 次十六进制或 rgb/rgba 颜色写法、130 种不同字面值。这是迁移规模指标，不等于 130 个有效设计 token。其余主要散落在选择器、HUD、会话样式中；4 个 TSX 文件有 inline style，须区分布局数值与主题值，不能机械删除。

当前运行时以 `resources/themes/{neon,graphite}/theme.json` 为内置主题包，以 `<WORKSPACE_ROOT>/themes/<id>/theme.json` 为用户包。`shared/themes/schema.ts` 定义严格协议，服务扫描后返回已解析的主题目录；前端统一将同一份主题转换为 CSS 变量和 Three 材质。`src/design/tokens.css` 是内置包的生成产物；浏览器同步载入同一内置包作为首屏回退。旧 `tokens.json` 与 `graphite.json` 已移除，不再维护平行颜色来源。历史 blue/orange/purple 键只存在于内部兼容适配，作者使用语义键。

设置页的界面外观分区从主题目录渲染名称、简介和预览。主题包在应用构建和启动后放入目录，刷新页面即可发现。浏览器保存所选 ID 并跨标签页同步，业务日期、动作、肌肉与未保存的设置草稿不因换肤清空。非法包单独隔离；确定移除的所选主题回退 Neon；目录暂时读取失败不能当作卸载并覆盖偏好。

Neon 保留局部控件光晕和重点肌肉自发光；Graphite 保留安静表面及冷暖中性色带。新主题通过 `effects`、`material`、`typography`、`body` 参数声明外观，产品组件不按具体主题 ID 分支。旧 `glowEnabled` 偏好字段仅作兼容，不覆盖主题的光效声明。

第三方包支持包内 PNG/WebP 预览和 WOFF2 字体，缺失可选资源使用回退并报告诊断。资源只从明确声明槽位读取，不开放整个目录。主题协议 v1 仅支持暗色；Agent iframe 内部 CSS 与 Host token 仍是独立边界。本轮不实现 Bloom、在线商店、自动更新、任意 CSS/JS 或布局插件。

## 2. 青／洋红方向板

最新色阶与光效契约以 [DESIGN.md 第 7.1 节](DESIGN.md#71-neon-三阶配色--已确认并接入主站) 为准。青色为 #00E5FF / #57B8C3 / #789DA2，偏红洋红为 #FF477E / #CB718C / #AA8792。样板支持两组独立选色及控件光晕／材质自发光分别开关；以下强调色表不另定义色阶。

定位：Neon Biometric。冷黑背景，青色能量信号，洋红空间焦点；通过暗底、局部高亮和亮暗间隔形成霓虹感。

| 角色 | 已确认色值 | 使用依据 | 禁止用途 |
| --- | --- | --- | --- |
| Canvas | `#070912` | 大面积安静承托人体 | 全屏彩色渐变 |
| Surface / Raised | `#111422` / `#1B2032` | 有内容的承载层 | 每层都加彩色描边 |
| Text / Muted | `#F1F5FF` / `#A4AFC5` | 正文与解释保持清晰 | 长段正文发光 |
| Accent primary | `#00E5FF` | 通用交互与动作主练 | 暗示真实恢复状态 |
| Accent secondary | `#FF477E` | 选择焦点；动作参与采用中阶 #CB718C | 同时代表错误、危险、未恢复 |
| Warning | `#E5AD72` | 有文本说明的真实关注状态 | 作为第三个常驻品牌色 |

两个 accent 是外观值；`interaction.focus`、`body.selected`、`body.exercise.primary/secondary` 才是消费角色。在不同明确模式中可以引用同一 accent，但图例、肌肉名称和形态必须辅助辨认。负荷映射与主练／参与映射独立，不能把洋红直接绑定现有 `purple` status。现有估算公式不随主题改变。

光效规则：普通容器 0；悬停只增强边界与亮度；焦点使用局部短光晕；每个场景最多一个主行动有扩散光晕。主站 token 当前使用 16px 内层与 36px 弱扩散；样板保留 18px／44px 作为比较参数，不能直接铺满主站。Graphite 的光晕为 none，减少材质自发光，证明“无霓虹”也是完整主题。

真实 3D 的 emissive 只增加材质自发光，不自动产生屏幕空间 halo。本轮样板明确标出该限制；Selective Bloom 需要独立测曝光、阈值、透明肌肉遮挡及移动端开销。避免用整个 Canvas 的 CSS blur 模拟真实局部光晕。无论主题如何，关闭 Bloom 后仍须辨认主练、参与与焦点。

2026-09-30 用户选定独立色卡中的柔和桥接。Neon 人体正值负荷改用七色标连续插值，当时新增内部 `body-load-1…5`，两端复用 accent／selection；主题包 v1 后完整七色统一来自 `body.loadColors`。色卡、Three 与左下角完整色带同源。零负荷保持灰色；Graphite、动作角色、焦点和其他 status 消费位置不变。领域计算不修改，完整显示边界以 `DESIGN.md` 第 7.3 节为准。色卡方向获选，真实人体版本仍待用户审阅。

用户随后要求直接接入 Graphite 连续色带，省略色卡提案。当前 Graphite 包以 `body.loadColors` 声明完整七色冷暖中性梯度，人体和图例复用既有插值逻辑；不改变光晕、自发光、动作和焦点配置。Graphite 人体正值负荷不再按离散 status 取色，其他 status 消费方保持原样。契约见 `DESIGN.md` 第 7.4 节，实际视觉效果待审阅。

## 3. 分离边界

```text
产品状态：模式 / 日期 / 肌肉选择 / 负荷语义
             ↓
产品组件：BodyCanvas / Tools / SpatialAnnotation / ContextPanel
             ↓ 只请求语义角色
主题解析器：默认值 → 已校验主题覆盖 → 有界用户偏好
             ├─ DOM 适配器 → CSS custom properties
             ├─ 3D 适配器 → 颜色 / emissive / roughness / 有界灯光强度
             └─ Agent 适配器（后续）→ 受验证主题消息 → Host theme tokens
```

| 留在产品核心 | 可由主题决定 | 第一阶段不开放 |
| --- | --- | --- |
| 信息顺序、身体安全区、抽屉行为、断点、点击区下限 | 语义颜色、字体预设／包内字体、圆角、弱边界、阴影 | 主题自带任意 CSS 选择器、JS、React 组件 |
| canonical 肌肉、状态含义、图例名称、操作结果 | 材质外观、有限灯光与光效参数 | 覆盖 API、业务规则、3D 映射 |
| 焦点可见性、reduced motion 行为、错误恢复 | 有界动效时间、表面边缘动效 | 重排流程、隐藏警示、把输入框替换为插件控件 |

圆角会影响布局，须限制范围并跨主题回归。亮色主题涉及透明身体、深浅表面与图表，需要单独适配，不能把 Graphite 暗色对照当成亮色支持证据。

当前结构 CSS 按功能组件组织，主题生成器继续使用 `--accent` 等语义变量；此前提案中的 `--fitness-*` 命名空间尚未迁移。新增样式复用现有语义变量，不手写品牌色。禁止新增长期规则依赖具体主题 ID，例如在业务组件里写 `if (theme === 'cyberpunk')`。样板中的 flat palette 仅用于桥接现有渲染器，不能直接成为外部包公开 API。

### 已实施的主题包 v1

包的最小必需字段为 `schemaVersion: 1`、`id`、`name`、`version` 与 `appearance: "dark"`；其余白名单字段使用协议默认值。完整字段、范围、默认值、字体与预览声明见 [作者指南](THEME-PACK-AUTHORING.md)。模板位于 `examples/themes/slate-studio/`，校验入口为 `npm run validate:theme -- <包目录>`。

服务每次读取主题目录时执行 schema、目录归属和资源边界检查。包不能覆盖 API、业务规则、人体映射、键盘行为或页面布局。未知键、非法数值、不兼容版本和 ID 冲突提供诊断。DOM 与 3D 使用统一解析后的主题；资源缺失走可读回退。

Agent 同步继续作为后续独立增量：需通过可信 origin/source 的桥接机制与 Host 协议，iframe 加载／重连后重发并确认。父页面换肤不能当作 Agent 同步证据。

## 4. 原始工作量估算（实施前范围，不是剩余工时）

估算基于当前代码审计，由一名熟悉 React / Three 的开发者实施、有人及时审图；1 人日按 6–8 小时有效工作计。包含实现与验证，不含用户等待时间；不是自动执行时间承诺。下列主线工项相加，无重复计费。

| 主线工项 | 人日 | 验收结果 |
| --- | ---: | --- |
| 方向板、两主题标准场景、规则冻结 | 2–3 | 桌面／手机参考明确、标记批准日期 |
| 语义 token、类型、解析、DOM／3D 接口 | 2–3 | 两主题使用相同产品组件与业务状态 |
| 现有 CSS 拆分迁移、内置切换、偏好持久化 | 3–5 | 核心模式与设置页不混色、首帧无闪烁 |
| 人体材质调校、局部 Bloom POC 与降级 | 2–3 | 桌面／手机实测记录；不达性能门槛则保留关闭 |
| 样板矩阵、交互与对比度检查、文档门槛 | 2–3 | 固定数据、模式和视口，可重复审阅 |
| **主站两套内置主题小计** | **11–17** | **约 2–3.5 个工作周** |
| Agent iframe / Host 主题同步 | +2–4 | 真实 Host 重连、刷新与两主题验收 |
| 本地 JSON 主题包导入和生命周期 | +3–5 | 非法包回退、预览／应用／删除／默认恢复 |
| **含 Agent 与本地可载入主题包** | **16–26** | **约 3–5.5 个工作周** |

估算已有范围余量；若 POC 发现透明模型 Bloom 有明显问题，需回到效果取舍，不自动追加渲染框架重写。真实低端移动设备与 Host 验证环境不可用会增加日历时间。

可另选：只改青／洋红和局部 DOM 发光约 1–2 人日，不能完成主题体系；亮色主题另加约 3–5 人日。若允许第三方 JS／CSS／布局组件插件，需增加扩展 API、隔离、版本兼容与故障恢复，粗估在上述基础上再加 15–30 人日，当前证据不足以给固定工期，不推荐作为第一阶段。

主线完成后，遵循现有结构的新暗色主题估计 1–3 人日含审图；每个主题都要进入回归矩阵。主题越多，后续组件变更验证成本越高，不存在一次建设后零维护。

## 5. 可持续遵守的契约

每条准则记录：编号、目的、正例、反例、适用状态、自动检查或人工验收方式、例外理由。建议首批冻结：

- V01 身体安全区：标准视口下头／手／脚不被工具栏或 Sheet 遮挡；截图与几何检查配合，不使用“70% 注意力”作为自动测试结论。
- V02 模式可辨：Overview / Day / Exercise / Muscle Focus 的图例与标题同步；主题切换不能清除选择或日期。
- V03 颜色冗余：主练／参与／焦点有名称或形态提示；洋红不复用危险语义。
- V04 光效预算：正常控件、正文无常驻光晕；重点区域与单一主行动例外；弱化光效后仍可读。
- V05 组件边界：固定语义角色取值，禁止业务分支判断主题名；新增主题色不得直接落入业务 JSX。
- V06 对比与操作：正文 4.5:1，必要的大文字及非文本控件按适用 AA 条件验证；点击区至少 44px，焦点轮廓不能只靠阴影。当前样板未完成完整 AA 认证。
- V07 基线批准：样板截图状态为 draft / approved / superseded；只有明确审阅通过才可将其设为视觉回归基线。生成或更新截图不等于批准。

回归至少覆盖 2 主题 × 4 主模式 × 2 视口，共 16 个标准场景；再加加载、无历史、错误、长动作名、键盘焦点和弱化动效用例。选择器与 Agent 另设覆盖。自动检查负责 token、schema、溢出和差异发现；审图负责视觉层级和空间关系。

主站统一采用 GlassCard 材质，四角 HUD 使用 quiet 层级，明确允许四角名称／核心数值，禁止叠加额外常驻指标卡。展开时加深玻璃层，保持人体优先。未来规则变更需更新 DESIGN.md、样板和基线记录，不能仅改代码。
